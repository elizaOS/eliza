# LifeOpsBench corpus audit

This inventory covers every registered runtime scenario and persona. The
machine-readable source of truth is [`corpus-audit.json`](./corpus-audit.json),
generated by executing every STATIC ground-truth action against LifeWorld and
classifying its observed effect.

## Corpus-wide result

- 1,501 base scenarios: 744 STATIC and 757 LIVE.
- 16,511 total runs: each base case plus ten model-directed language
  challenges.
- 1,501/1,501 publishable openings are generated by the independent persona
  model; no authored hidden goal is delivered to the executor.
- 32/32 persona IDs come from the canonical persona library.
- 734 STATIC scenarios declare semantic response-output contracts.
- 53 LIVE scenarios require cryptographically verified provider evidence.
- 239 modeled mutation occurrences and 242 classified modeled no-mutation
  occurrences were exercised during the deterministic audit.
- Zero successful no-effect gaps, zero unclassified successful no-effects, and
  zero audit execution errors.

Publishable STATIC and LIVE runs both use simulated openings. STATIC structural
facts are still checked deterministically, but response facts and rubrics are
graded by an independent model in one strict structured verdict. The explicit
offline-conformance lane uses authored STATIC text and literal canaries only for
harness diagnostics; its results cannot be published.

## Inference and deterministic-protocol boundary

The persona model sees a profile, hidden goal, optional language challenge,
and current world snapshot. It does not receive success criteria, world
assertions, required outputs, or static rubrics. The ten edge variants direct
vagueness, referential language, self-correction, colloquial or noisy language,
code switching, underspecification, stress, relative time, and fragmented
handoffs without prepending fixed text or changing the hidden goal.
Near-verbatim goal leakage fails before the executor runs.

The independent judge receives stable transcript line IDs and returns one
strict JSON criterion record for every requested `output_N` and `rubric_N`.
Missing, duplicate, unexpected, malformed, or non-boolean records invalidate
the whole verdict. Positive grades require a meaningful exact quote from an
eligible executor or tool line; user text and unauthenticated trusted-tool
payloads cannot supply evidence.

Remaining conditionals implement protocol structure: action/discriminator
routing, schema validation, deterministic world mutation, receipt
authentication, and strict verdict parsing. They do not classify user intent
from phrases. Scheduled-task create calls omit server-owned IDs; dependent
turns use the deterministic executor receipt identity, and corpus validation
rejects mutation targets without seeded state or a preceding create receipt.

PerfectAgent, WrongAgent, deterministic adapters, fake backends, and fixed
evaluator clients are conformance fixtures only. They cannot produce
publishable benchmark evidence. The 53 evidence-gated scenarios additionally
require authenticated terminal provider artifacts; a LifeWorld mutation or
model claim cannot satisfy that gate.
