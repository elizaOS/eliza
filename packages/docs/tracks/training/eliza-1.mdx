Eliza-1 is the open-weight model line developed for native Eliza agent
trajectories and tool calls. The canonical training and release contract lives
in [`packages/training/`](https://github.com/elizaOS/eliza/tree/develop/packages/training);
the runtime and model downloader live outside that package.

## Model tiers

The current registry maps four Gemma 4 bases to public Eliza-1 tiers:

| Registry key | Eliza-1 tier | Base | Intended target |
| --- | --- | --- | --- |
| `gemma4-e2b` | `eliza-1-2b` | `google/gemma-4-E2B` | Local and entry hardware |
| `gemma4-e4b` | `eliza-1-4b` | `google/gemma-4-E4B` | Local workstation |
| `gemma4-12b` | `eliza-1-9b` | `google/gemma-4-12B` | Workstation GPU |
| `gemma4-31b` | `eliza-1-27b` | `google/gemma-4-31B` | Cloud GPU |

`elizaos/eliza-1-2b` is the locked real model used by the continuous-RL
configuration. Release bundles are published under
[`elizaos/eliza-1`](https://huggingface.co/elizaos/eliza-1), while training
data and pipeline snapshots use `elizaos/eliza-1-training`.

## Training and evaluation

The pipeline fine-tunes text and the matching speculative-decoding drafter.
Voice and ASR weights are frozen and evaluated as release assets rather than
retrained. APOLLO is the required optimizer; the smaller tiers use the
low-rank `apollo_mini` profile.

The release graph is:

```text
base benchmark
  -> APOLLO supervised fine-tuning
  -> fine-tuned benchmark
  -> GGUF K-quant artifacts and MTP manifest
  -> quantized benchmark
  -> gated bundle publication
```

Continuous training data comes from the native trajectory recorder under the
resolved Eliza state directory. Recording is opt-in in production and test;
the scenario runner enables it for evaluation runs.

## Quantization

The shipping Gemma path uses llama.cpp GGUF K-quants, currently Q4_K_M for the
local release tier with Q6_K and Q8_0 where a tier requires them.

The package also contains specialized recipes with different roles:

| Recipe | Role in the current pipeline |
| --- | --- |
| TurboQuant | Runtime V-cache compression; it does not quantize model weights. |
| QJL | Runtime K-cache compression using JL projection. |
| PolarQuant | Linear-weight quantization with sidecar artifacts. |

Those recipes are optional for the current Gemma release line unless a tier
explicitly enables them and carries real verification evidence. Their presence
in the source tree does not mean every published bundle uses them.

## Run locally with Ollama

The training package includes Ollama Modelfiles for released tiers. After
obtaining the referenced GGUF artifact, create a local model from the repository
root:

```bash
ollama create eliza-1-2b \
  -f packages/training/cloud/ollama/Modelfile.eliza-1-2b-q4_k_m
```

Ollama integration is an explicitly installed provider path; it is not part of
the current environment-variable auto-detection map. Embedded packaged builds
use `@elizaos/plugin-local-inference` and their platform-specific model catalog.

## Release guarantees

The publisher refuses a bundle when required model, kernel, hardware, or
evaluation evidence is missing. Published manifests bind the text checkpoint,
drafter, quantized files, licenses, and evaluation results so a runtime can
verify that it is loading one coherent bundle.
