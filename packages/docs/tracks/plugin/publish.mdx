---
title: Publish a Plugin
description: "Ship your plugin to npm so any agent can install it."
---

elizaOS plugins are plain npm packages. Publishing is `npm publish` with a small set of conventions.

## Naming

Use the `@elizaos/plugin-<name>` scope when contributing to the core registry, or your own scope (`@your-org/plugin-<name>`) for private / third-party plugins. Agents reference plugins by package name in their character's `plugins` array.

## Build

```bash
bun run build
```

The default template uses Bun to produce an ESM runtime bundle and TypeScript
declarations under `dist/`. Verify `main`, `module`, `types`, and `exports`
point into that directory.

## Test

```bash
bun run test
bun run test:e2e
```

E2E tests boot a real `AgentRuntime` with your plugin loaded — they catch boot-time registration failures that unit tests miss.

## Publish

```bash
npm publish --access public
```

Use an explicit prerelease dist-tag so you do not move npm's `latest` tag:

```bash
npm publish --tag beta --access public
```

## Discovery

A character can load any installed plugin package. npm packages whose keywords
include `elizaos` are recognized for discovery; curated registry submission is
documented in the full publish guide.
