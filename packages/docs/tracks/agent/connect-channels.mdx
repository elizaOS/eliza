Messaging integrations are plugins selected from the `connectors` section of
`eliza.json`. Adding a non-disabled connector entry causes the runtime to load
the package mapped to that connector by the first-party registry.

## Supported connectors

This table mirrors
[`packages/registry/src/first-party/channel-plugin-map.json`](https://github.com/elizaOS/eliza/blob/develop/packages/registry/src/first-party/channel-plugin-map.json).
Required settings come from the generated first-party registry metadata.

| Connector key | Plugin package | Required setting |
| --- | --- | --- |
| `blooio` | `@elizaos/plugin-imessage` | `IMESSAGE_BLOOIO_API_KEY`, `IMESSAGE_BLOOIO_WEBHOOK_SECRET`, `IMESSAGE_BLOOIO_FROM_NUMBER`, `IMESSAGE_BLOOIO_CHANNEL_ID` |
| `discord` | `@elizaos/plugin-discord` | `DISCORD_API_TOKEN` |
| `discordLocal` | `@elizaos/plugin-discord` | See the plugin's local-account setup |

| `mattermost` | `@elizaos/plugin-mattermost` | `MATTERMOST_BOT_TOKEN` |

## Configure a connector

Add a connector entry to the canonical config file. Connector-specific fields
are projected to the environment variables expected by the plugin.

```json5
// ~/.local/state/eliza/eliza.json
{
  connectors: {
    discord: {
      token: "<discord-bot-token>",
      applicationId: "<discord-application-id>",
    },
  },
}
```

An entry is enough to select the mapped plugin unless `enabled` is explicitly
`false`. You can also put plugin settings directly in the process environment
or the config's `env.vars` section. Restart the runtime after changing connector
credentials.

<Warning>
Do not commit connector tokens. The config file may contain secrets and should
remain owner-readable only; environment variables or the app's credential UI
are preferable for shared projects.
</Warning>

## iMessage: native or Blooio

`@elizaos/plugin-imessage` has two distinct transports. Native mode reads the
local Messages database and sends through Messages.app, so it requires macOS,
an active iMessage account, Full Disk Access for message history, and Automation
permission for sending. Select it with an `imessage` connector entry:

```json5
// ~/.local/state/eliza/eliza.json
{
  connectors: {
    imessage: { enabled: true },
  },
  env: {
    vars: {
      IMESSAGE_TRANSPORT: "native",
    },
  },
}
```

Blooio mode is the hosted alternative and does not use Messages.app or
`chat.db`. Select the plugin with a `blooio` connector entry and provide the
complete Blooio transport contract through the credential UI or `env.vars`:

```json5
// ~/.local/state/eliza/eliza.json
{
  connectors: {
    blooio: { enabled: true },
  },
  env: {
    vars: {
      IMESSAGE_TRANSPORT: "blooio",
      IMESSAGE_BLOOIO_API_KEY: "<api-key>",
      IMESSAGE_BLOOIO_WEBHOOK_SECRET: "<webhook-signing-secret>",
      IMESSAGE_BLOOIO_FROM_NUMBER: "+15551234567",
      IMESSAGE_BLOOIO_CHANNEL_ID: "<channel-id>",
    },
  },
}
```

Configure Blooio to deliver signed webhooks to
`/api/imessage/webhook/blooio` on the agent's public origin. The configured
channel ID must exactly match the inbound webhook channel; the plugin rejects
unsigned deliveries and deliveries for any other channel.

## Find every supported field

The registry is the source of truth for credential names, required fields, help
text, and validation constraints:

- [`generated.json`](https://github.com/elizaOS/eliza/blob/develop/packages/registry/src/first-party/generated.json) contains the generated connector records.
- [`CONNECTOR_ENV_MAP`](https://github.com/elizaOS/eliza/blob/develop/packages/agent/src/config/env-vars.ts) shows how `connectors.<name>` fields become environment variables.
- The plugin's `registry-entry.json` and README document platform setup, scopes, webhook configuration, and optional behavior.

For a connector not listed above, install and enable its plugin explicitly. Do
not assume that an older connector name is still recognized by the runtime.
