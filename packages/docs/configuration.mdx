The runnable agent stores bootstrap and runtime settings in `eliza.json`. The
canonical TypeScript shape is
[`ElizaConfig`](https://github.com/elizaOS/eliza/blob/develop/packages/shared/src/config/types.eliza.ts),
and the settings API exposes field metadata for UI consumers. This page covers
the stable configuration contract; plugin-specific options belong in each
plugin's registry entry and README.

## File location

The state-directory resolver uses this precedence:

1. `ELIZA_STATE_DIR`
2. `$XDG_STATE_HOME/${ELIZA_NAMESPACE}`
3. `~/.local/state/${ELIZA_NAMESPACE}`

`ELIZA_NAMESPACE` defaults to `eliza`, so the normal config path is
`~/.local/state/eliza/eliza.json`. `ELIZA_CONFIG_PATH` overrides the read path
directly. `ELIZA_PERSIST_CONFIG_PATH` is an advanced override for the file
written by the settings service.

```bash
ELIZA_STATE_DIR=/srv/eliza-state bun run start
ELIZA_CONFIG_PATH=/srv/eliza/config.json5 bun run start
```

The same state directory contains runtime-owned data such as credentials,
installed plugins, model catalogs, trajectories, and skills. Code should use
the shared state-directory helpers instead of rebuilding these paths.

## Format and includes

The loader accepts JSON5, including comments, trailing commas, quoted or
unquoted keys, and single-quoted strings.

```json5
{
  logging: { level: "info" },
  agents: {
    defaults: { workspace: "/srv/eliza/workspace" },
  },
}
```

`$include` composes files relative to the file containing the directive:

```json5
{
  $include: ["./base.json5", "./connectors.json5"],
  logging: { level: "debug" },
}
```

Objects merge recursively, arrays concatenate, and sibling values override
included scalar values. Includes are limited to 10 levels; circular includes,
unreadable files, and parse failures throw configuration errors. When the app
saves config, include directives are removed and the resolved object is
written as JSON.

## Runtime topology

These top-level fields are the persisted source of truth for where the runtime
runs and which backends serve it:

| Field | Purpose |
| --- | --- |
| `deploymentTarget` | Selects a `local`, `cloud`, or `remote` runtime. |
| `linkedAccounts` | Records linked-account status flags. Credential records live separately under the state directory. |
| `serviceRouting` | Assigns capabilities such as `llmText`, `tts`, media, embeddings, and RPC to backends. |

Use the Settings UI or provider-switch API to change topology when possible;
those paths normalize the three fields together. See [Model providers](/model-providers)
for direct-provider loading.

## Main sections

Every section is optional. This is the current top-level organization, grouped
by responsibility rather than duplicated field-by-field from the source type.

| Area | Sections |
| --- | --- |
| File metadata and bootstrap | `meta`, `wizard`, `env`, `auth`, `update` |
| Runtime placement and routing | `deploymentTarget`, `linkedAccounts`, `serviceRouting`, `cloud`, `cua` |
| Agents and model behavior | `agents`, `models`, `memory`, `embedding`, `roles`, `skills`, `customActions` |
| Extension loading | `plugins`, `features`, `connectors`, `streaming`, `mcp`, `hooks`, `workflow` |
| Tools and automation | `tools`, `commands`, `approvals`, `cron`, `browser`, `nodeHost`, `x402` |
| Messaging and media | `messages`, `audio`, `talk`, `media`, `web`, `bindings`, `broadcast` |
| Storage and platform services | `database`, `documents`, `wallet`, `registry`, `discovery`, `gateway` |
| Presentation and operations | `ui`, `logging`, `diagnostics`, `session` |

For the exact nested types and comments, use the linked `ElizaConfig` source.
Unlike a copied schema table, it changes in the same commit as the runtime.

## Environment values

`env.vars` and direct string properties under `env` are applied to the runtime
process. Values stored by the app's protected config-env service are also
hydrated at startup without being copied back into `eliza.json`.

```json5
{
  env: {
    vars: {
      OPENAI_API_KEY: "<api-key>",
    },
  },
}
```

Shell import is opt-in:

```json5
{
  env: {
    shellEnv: {
      enabled: true,
      timeoutMs: 15000,
    },
  },
}
```

The loader invokes the login shell only to fill missing environment values.
Prefer the app credential store or process environment for secrets that should
not appear in the config file.

## Plugins

The plugin load configuration is additive:

```json5
{
  plugins: {
    allow: ["discord", "@acme/plugin-weather"],
    deny: ["@elizaos/plugin-example"],
    load: { paths: ["./plugins/plugin-local"] },
    entries: {
      discord: { enabled: true },
      anthropic: { enabled: false },
    },
    slots: { memory: "@elizaos/plugin-sql" },
  },
}
```

`allow` adds packages to the automatically selected set; it is not an
exclusive allowlist. Short first-party IDs are expanded by the runtime.
`entries.<id>.enabled: false` explicitly suppresses a plugin. Installed-plugin
records are runtime-managed and should not be edited manually.

## Connectors

Any non-disabled object under `connectors.<channel>` selects the package mapped
to that channel by the registry. Known config fields are projected to the
environment variables consumed by the plugin.

```json5
{
  connectors: {
    telegram: {
      botToken: "<telegram-bot-token>",
    },
    discord: {
      token: "<discord-bot-token>",
      applicationId: "<discord-application-id>",
    },
  },
}
```

See [Connect channels](/tracks/agent/connect-channels) for the current registry
mapping and required credentials.

## Agents

Shared agent settings live under `agents.defaults`; per-agent overrides live
under `agents.list`.

```json5
{
  agents: {
    defaults: {
      workspace: "/srv/eliza/workspace",
      model: { primary: "@elizaos/plugin-openai" },
    },
    list: [
      {
        id: "assistant",
        name: "Assistant",
      },
    ],
  },
}
```

Use stable IDs for entries referenced by bindings or broadcast rules.

## Persistence and safety

The settings service writes atomically through a temporary file and enforces
owner-only mode (`0600`) where the platform supports POSIX permissions. If the
config path is a symlink, it updates the target rather than replacing the
symlink. With OS-backed wallet storage enabled, private wallet keys are removed
before serialization.

<Warning>
Owner-only permissions reduce accidental disclosure but do not make plaintext
secrets portable or shareable. Do not commit `eliza.json` when it contains
credentials.
</Warning>

## Diagnose a configuration problem

1. Confirm the resolved state directory and config path.
2. Parse the file as JSON5 and resolve every `$include` path.
3. Check startup logs for include, plugin import, and routing errors.
4. Confirm settings are present in the runtime process, not only the client or
   parent shell.
5. Compare the field with `ElizaConfig` and the owning plugin's registry entry.
6. Restart after changes that affect plugin loading or runtime topology.

The live config UI schema is served by the agent settings API and built in
[`packages/agent/src/config/schema.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/agent/src/config/schema.ts).
