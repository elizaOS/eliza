---
title: Create a Project
description: "Scaffold a new Eliza agent project."
---

```bash
npx elizaos create [name] --template project
```

## Flags

| Flag                              | Purpose                                                          |
| --------------------------------- | ---------------------------------------------------------------- |
| `-t, --template <template>`       | `project` (default) or `plugin`.                                 |
| `-l, --language <lang>`           | Template language. TypeScript is the only shipping option today. |
| `-y, --yes`                       | Skip confirmation prompts.                                       |
| `--skip-upstream`                 | Don't initialize a local `eliza/` upstream checkout.             |

## What you get

The `project` template scaffolds a package-first product workspace:

- `apps/app/` — branded web, desktop, and mobile app shell.
- `eliza/` — the local upstream checkout initialized by the template.
- `package.json` — project-level development, build, test, lint, and typecheck scripts.
- `scripts/` — source-mode and app-core command adapters.
- `.elizaos/template.json` — managed-file hashes and template metadata used by `upgrade`.
- `.env.example` and `apps/app/.env.example` — runtime and app environment templates.

The default project initializes the `eliza/` upstream checkout. Set
`--skip-upstream` when you intentionally want only the generated shell.

## Next steps

```bash
cd <name>
bun install
cp .env.example .env   # fill in model provider key
bun run dev
```

`bun run dev` starts the generated project's development workflow. There is no
`elizaos start`; running the product is a project script, not a scaffold-CLI
command.
