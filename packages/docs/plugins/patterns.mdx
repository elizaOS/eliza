---
title: "Plugin patterns"
description: "Current patterns for reliable elizaOS actions, providers, services, and routes."
---

Start from the [maintained plugin template](/plugins/create-a-plugin). The
patterns below cover the decisions that matter once a plugin grows beyond the
starter example.

## Keep component responsibilities narrow

| Component | Responsibility | Must not do |
| --- | --- | --- |
| Action | Validate and execute a user- or agent-requested operation | Hide a failed effect behind `success: true` |
| Provider | Read context for prompt and state composition | Commit external side effects |
| Service | Own a long-lived client, resource, or scheduler | Return before required initialization finishes |
| Evaluator | Process the result of a completed response | Replace the action's authoritative effect result |
| Route | Translate an HTTP boundary to typed application logic | Contain business computation |

## Return explicit action results

```typescript
import type { Action } from "@elizaos/core";

export const savePreference: Action = {
  name: "SAVE_PREFERENCE",
  description: "Stores one owner preference",
  validate: async (_runtime, message) => Boolean(message.entityId),
  handler: async (runtime, message, _state, options) => {
    const key = String(options?.parameters?.key ?? "");
    const value = String(options?.parameters?.value ?? "");
    if (!key || !value) throw new Error("key and value are required");

    const preferences = runtime.getService<PreferenceService>("preferences");
    if (!preferences) throw new Error("Preference service is unavailable");
    await preferences.set(message.entityId, key, value);

    return {
      success: true,
      userFacingText: `Saved preference ${key}.`,
      data: { key, value },
    };
  },
};
```

Throw when the operation could not be completed. Do not turn exceptions into a
healthy-looking empty result. When an action performs an externally visible
mutation, return the applicable effect receipt fields so the runtime can ground
the completion claim.

## Put shared clients in services

Actions and providers should retrieve an initialized service instead of
creating a new API client per call:

```typescript
const client = runtime.getService<ApiService>(ApiService.serviceType);
if (!client) throw new Error("API service is unavailable");
```

The service owns connection setup, rate limiting, and teardown. See
[Runtime services](/runtime/services).

## Make providers cancellable

```typescript
async get(_runtime, message, _state, context) {
  const record = await repository.findByEntity(message.entityId, {
    signal: context?.signal,
  });
  return record
    ? { text: renderRecord(record), data: { record } }
    : { text: "No record exists.", data: { available: true, record: null } };
}
```

Distinguish a designed empty result from a failed load. Propagate the provider
abort signal to interruptible dependencies.

## Validate boundaries once

Validate configuration during plugin initialization and request bodies at the
route or action boundary. Pass typed values inward. Add context with a typed
error and `cause` when rethrowing; do not catch only to log and continue.

## Make teardown complete

Pair every timer, socket, listener, subprocess, or lease created by a service
with cleanup in `stop()`. Pair plugin-level resources with `dispose()`. Cleanup
should be safe to call after partial initialization.

## Test the assembled plugin

Unit-test pure parsing and validation, then run the plugin in a real runtime
with its actual adapter and service boundaries. Assert both the returned result
and the persisted or external artifact. See [Plugin testing](/plugins/testing).

The canonical component contracts are in
[`packages/core/src/types/components.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/core/src/types/components.ts)
and the plugin contract is in
[`packages/core/src/types/plugin.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/core/src/types/plugin.ts).
