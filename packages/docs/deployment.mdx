The maintained deployment assets live in `packages/app-core/deploy/`. That directory is the source of truth for image inputs, Compose services, defaults, and rollout helpers.

## Prerequisites

- Docker Engine with Docker Compose
- A checkout with dependencies and build artifacts available
- Provider credentials for the plugins your agent uses

## Local Docker setup

From the repository root:

```bash
bash packages/app-core/deploy/docker-setup.sh
```

The setup script builds the local image, creates the gateway token and environment file, runs interactive setup, and starts the Compose stack.

Check the running services:

```bash
docker compose +  --env-file deploy/.env +  -f packages/app-core/deploy/docker-compose.yml +  ps
```

Follow gateway logs:

```bash
docker compose +  --env-file deploy/.env +  -f packages/app-core/deploy/docker-compose.yml +  logs -f eliza-gateway
```

## Build the image directly

```bash
docker build +  -f packages/app-core/deploy/Dockerfile.ci +  -t eliza:local +  .
```

`Dockerfile.ci` pins Node.js 24 by default and assembles the prebuilt agent, app, and runtime dependency closure. Use the setup script unless you specifically need to control the image build yourself.

## Configuration

Shared defaults are in `packages/app-core/deploy/deploy.defaults.env`. Put app-specific overrides in `deploy/deploy.env`; the deployment helpers also accept an explicit file through `DEPLOY_CONFIG`.

Common settings include:

| Variable | Purpose | Default |
| --- | --- | --- |
| `APP_IMAGE` | Image used by the deployment helpers | `eliza:local` |
| `APP_PORT` | Agent API and app port in the image | `2138` |
| `APP_GATEWAY_PORT` | Gateway listener | `18789` |
| `APP_BRIDGE_PORT` | Inter-service bridge | `18790` |
| `APP_STATE_DIR` | Persistent state directory in the image | `/home/node/.eliza` |
| `APP_CONFIG_DIR` | Host directory mounted for configuration and state | `${HOME}/.eliza` |
| `APP_WORKSPACE_DIR` | Host directory mounted for agent workspace files | `${HOME}/.eliza/workspace` |
| `APP_API_BIND` | API bind address baked into the image | `127.0.0.1` |

See `packages/app-core/deploy/README.md` and `deploy.defaults.env` before adding an override; those files track the actual scripts.

## Security

- Set `ELIZA_API_TOKEN` whenever the API is reachable beyond localhost.
- Set `ELIZA_ALLOWED_ORIGINS` to the exact browser origins that need access.
- Keep the default loopback bind unless a reverse proxy or container network requires another address.
- Mount state and workspace directories explicitly; do not bake secrets into the image.
- Terminate TLS at a trusted reverse proxy for public deployments.

## Eliza Cloud

Eliza Cloud uses the separate `Dockerfile.cloud-agent` image and managed provisioning services. Use the [Cloud overview](/tracks/cloud/overview) when you want hosted agents rather than operating this Compose stack yourself.

## Troubleshooting

```bash
# Validate the resolved Compose configuration
docker compose +  --env-file deploy/.env +  -f packages/app-core/deploy/docker-compose.yml +  config

# Restart the gateway after changing deploy/.env
docker compose +  --env-file deploy/.env +  -f packages/app-core/deploy/docker-compose.yml +  up -d eliza-gateway
```

If a container is unhealthy, inspect its logs before restarting it. A missing provider key, invalid state directory, or mismatched port should surface as an error; do not treat an empty or partially initialized service as healthy.
