The runtime checks the npm `elizaos` package for releases on the `stable`,
`beta`, or `nightly` channel. The implementation lives in
[`packages/agent/src/services/update-checker.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/agent/src/services/update-checker.ts),
while the `eliza update` command is registered in
[`packages/app-core/src/cli/program/register.update.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/app-core/src/cli/program/register.update.ts).

## Commands

```bash
# Check and apply an update on the configured channel
eliza update

# Check without changing the installation
eliza update --check

# Bypass the four-hour result cache
eliza update --check --force

# Switch channel and update
eliza update --channel beta

# Show the installed version, install method, and all published channels
eliza update status

# View or change only the configured channel
eliza update channel
eliza update channel nightly
```

`eliza update --voice-models` lists the independently versioned voice-model
artifacts. Add `--check` to keep that operation read-only.

## Release channels

| Channel | npm dist-tag | Intended use |
| --- | --- | --- |
| `stable` | `latest` | Production releases. |
| `beta` | `beta` | Pre-release testing. |
| `nightly` | `nightly` | Latest development build. |

The effective channel comes from `ELIZA_UPDATE_CHANNEL`, then the `update.channel`
configuration field, then `stable`. The environment value must be exactly one
of the three channel names after trimming and lowercasing.

## Configuration

```json
{
  "update": {
    "channel": "stable",
    "checkOnStart": true,
    "checkIntervalSeconds": 14400
  }
}
```

`lastCheckAt` and `lastCheckVersion` are runtime-managed cache fields. A TTY CLI
startup performs a non-blocking check unless `checkOnStart` is `false`, the
process is running under `CI`, stderr is not a TTY, or the interval has not
elapsed. Registry failures do not interrupt startup.

## Who applies the update

The command resolves the installed `eliza` binary and delegates to its owner:

| Detected installation | Update owner |
| --- | --- |
| npm or Bun global package | The matching package manager installs `elizaos@<dist-tag>`. |
| Homebrew | `brew upgrade eliza`. |
| apt, Snap, or Flatpak | The operating-system package manager. |
| Source checkout | The developer updates the checkout; the CLI does not rewrite it. |
| Unknown | The CLI reports the ambiguity and has an npm fallback. |

The detailed mapping is defined in
[`packages/agent/src/services/self-updater.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/agent/src/services/self-updater.ts).
After a package-manager update, restart the running process so it loads the new
code.

<Warning>
  Pin or roll back with the same installer that owns the current installation.
  Downgrading across database or configuration migrations may not be safe; back
  up state before changing to an older release.
</Warning>

## Remote status API

Authenticated clients can inspect `GET /api/update/status` and change the
channel with `PUT /api/update/channel`. Remote responses expose the recommended
host command but deliberately do not provide a remote command-execution route.

```bash
curl "http://127.0.0.1:31337/api/update/status?force=true" \
  -H "Authorization: Bearer $ELIZA_API_TOKEN"

curl -X PUT "http://127.0.0.1:31337/api/update/channel" \
  -H "Authorization: Bearer $ELIZA_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"channel":"beta"}'
```
