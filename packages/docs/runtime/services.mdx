---
title: "Runtime services"
description: "Implement and consume long-lived capabilities managed by an elizaOS runtime."
---

Services own long-lived resources such as clients, schedulers, connectors, and
connection pools. The runtime starts registered service classes during
initialization and stops their instances during shutdown.

Use an action for one request-scoped operation. Use a service when state or a
resource must live across requests.

## Define a service

```typescript
import { Service, type IAgentRuntime } from "@elizaos/core";

export class WeatherService extends Service {
  static serviceType = "weather";
  capabilityDescription = "Fetches current weather observations";

  static async start(runtime: IAgentRuntime): Promise<WeatherService> {
    const service = new WeatherService(runtime);
    await service.connect();
    return service;
  }

  async getCurrent(city: string) {
    return this.client.current(city);
  }

  async stop(): Promise<void> {
    await this.client.close();
  }
}
```

`static serviceType`, `capabilityDescription`, `static start()`, and `stop()`
are required by the base contract. `start()` must return a ready instance or
throw; do not return a partially initialized service.

## Register and retrieve it

Plugins normally register the class declaratively:

```typescript
import type { Plugin } from "@elizaos/core";

export const weatherPlugin: Plugin = {
  name: "weather",
  description: "Adds weather observations",
  services: [WeatherService],
};
```

After runtime initialization, retrieval is synchronous:

```typescript
const weather = runtime.getService<WeatherService>("weather");
if (!weather) throw new Error("Weather service is not loaded");

const observation = await weather.getCurrent("Lisbon");
```

Services are singletons by type unless the class explicitly sets
`static allowsMultiple = true`. Use `getServicesByType()` for a multi-instance
type.

## Extend the type registry

Plugins can add a literal service type through module augmentation:

```typescript
declare module "@elizaos/core" {
  interface ServiceTypeRegistry {
    WEATHER: "weather";
  }
}
```

This gives callers a checked string while preserving an extensible registry.
The canonical interface and built-in service constants live in
[`packages/core/src/types/service.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/core/src/types/service.ts).

## Failure and cleanup

- Let initialization failures reject runtime startup when the capability is
  required.
- Report failures from background work through `runtime.reportError()` so the
  agent and operator can observe them.
- Keep shutdown idempotent and release timers, sockets, subprocesses, and
  external leases in `stop()`.
- Do not convert a failed read into an empty or zero result.

See [Plugin architecture](/plugins/architecture) for how services interact with
actions and providers.
