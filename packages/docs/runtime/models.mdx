---
title: "Runtime models"
description: "Register and call model implementations through the model-agnostic elizaOS runtime."
---

The runtime routes model requests by capability instead of by vendor. A model
plugin registers handlers for one or more `ModelType` values; callers use
`runtime.useModel()` without importing that provider's SDK.

## Call a model

```typescript
import { ModelType } from "@elizaos/core";

const answer = await runtime.useModel(ModelType.TEXT_LARGE, {
  prompt: "Explain content-addressed storage in two sentences.",
  temperature: 0.4,
});
```

Text-generation calls return a string. Other model types have their own
parameter and result shapes, enforced by `ModelParamsMap` and `ModelResultMap`.
The current contracts live in
[`packages/core/src/types/model.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/core/src/types/model.ts).

## Built-in capabilities

The stable capability groups are:

- text generation: nano, small, medium, large, mega, reasoning, completion,
  response handling, and action planning;
- embeddings and batch embeddings;
- tokenizer encode and decode;
- image generation and description;
- transcription, speech, audio, and video;
- research and privacy scrubbing.

Use the exported constants rather than copying their string values:

```typescript
await runtime.useModel(ModelType.TEXT_EMBEDDING, {
  text: "A memory to embed",
});
```

This keeps application code compatible when the registry grows.

## Provider selection

Several plugins may register the same capability. The runtime chooses the
highest-priority compatible registration. Pass a provider name as the optional
third argument only when a call must target a particular registration:

```typescript
const answer = await runtime.useModel(
  ModelType.TEXT_SMALL,
  { prompt: "Summarize this conversation." },
  "openai",
);
```

Provider availability is determined by the loaded plugins and their valid
configuration. A missing or failed model handler rejects the call; it does not
fabricate an empty result.

## Implement a model plugin

Declare handlers in the plugin object. The key determines the typed parameter
and result contract:

```typescript
import { ModelType, type Plugin } from "@elizaos/core";

export const modelPlugin: Plugin = {
  name: "example-model-provider",
  description: "Provides text generation for the example service",
  models: {
    [ModelType.TEXT_SMALL]: async (_runtime, params) => {
      const response = await callProvider(params.prompt);
      if (!response.text) throw new Error("Provider returned no text");
      return response.text;
    },
  },
};
```

Keep credentials and provider-specific retry policy inside the plugin. Callers
should depend only on the runtime capability.

## Model settings

Direct call parameters have the highest precedence. Character settings can set
per-capability values such as `TEXT_SMALL_TEMPERATURE`, followed by defaults
such as `DEFAULT_TEMPERATURE`. See the exported `MODEL_SETTINGS` object for the
complete current key set.

For installing and configuring maintained model plugins, see
[Model providers](/model-providers).
