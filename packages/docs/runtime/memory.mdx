title: "Runtime memory and state"
description: "Store conversation records and compose turn-scoped state in elizaOS."

A `Memory` is the persisted unit used for messages, documents, fragments, and
other agent records. `State` is the transient context assembled for one turn.
They are related but not interchangeable: memory survives through the database
adapter, while state is recomputed from providers and the current message.

For the conceptual agent-memory model, see [Agent memory](/tracks/agent/memory).

## Memory shape

```typescript
import type { Memory } from "@elizaos/core";

const memory: Memory = {
  entityId,
  roomId,
  content: { text: "The deployment starts at 09:00 UTC." },
  createdAt: Date.now(),
  metadata: {
    type: "message",
    scope: "room",
  },
};
```

The required fields are `entityId`, `roomId`, and `content`. IDs use the core
`UUID` type, and `createdAt` is milliseconds since the Unix epoch. Embeddings,
world and agent IDs, session identifiers, similarity scores, and typed metadata
are optional.

The complete current contracts are in
[`packages/core/src/types/memory.ts`](https://github.com/elizaOS/eliza/blob/develop/packages/core/src/types/memory.ts).

## Store a memory

```typescript
const memoryId = await runtime.createMemory(memory, "messages");
const stored = await runtime.getMemoryById(memoryId);

if (!stored) throw new Error(`Memory ${memoryId} was not found`);
```

The table name identifies the logical memory table used by the configured
database adapter. Prefer runtime methods over reaching into the adapter so
secret handling, embedding, and runtime invariants remain applied.

## Embeddings

`addEmbeddingToMemory()` generates an embedding immediately.
`queueEmbeddingGeneration()` schedules it asynchronously with a high, normal,
or low priority. A failed embedding operation surfaces as a failure; callers
must not substitute a zero vector.

Semantic-search results may set `similarity` on returned memories. Treat that
as retrieval metadata rather than persistent content.

## State composition

```typescript
const state = await runtime.composeState(message, [
  "ACCOUNT_STATUS",
  "RECENT_MESSAGES",
]);

const prompt = state.text;
const accountTier = state.values.accountTier;
```

State contains rendered `text`, template `values`, and structured `data`.
Providers contribute those fields according to context and access gates. See
[Runtime providers](/runtime/providers).

## Scope and privacy

Memory metadata can express shared, room, global, owner-private, user-private,
and agent-private scopes. Enforcement belongs at storage, retrieval, and prompt
composition boundaries. A prompt instruction is not an access-control check.

Keep attachment bytes in the content-addressed media store and reference them
through `Media`; do not create a second file store inside a memory plugin.
