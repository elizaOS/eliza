## Recovery

[`production-ledger-recovery-20261023.sql`](production-ledger-recovery-20261023.sql) is generated by [`production-ledger-recovery-20261023.ts`](production-ledger-recovery-20261023.ts) from the canonical journal. The test pins the committed SQL to the generator's output. It runs as one transaction:

1. Locks the ledger. Before any mutation it refuses:
   - any ledger other than the reviewed 373 rows, compared by every id, hash and `created_at`;
   - any schema where an object of the six already-effective migrations is missing or differs from [the reviewed fingerprint](fixtures/production-ledger-recovery-20261023-effects.json). The error names each such object.
2. Archives rows 371–373 into `drizzle.__drizzle_migrations_retired_20261023`.
3. Restarts the id sequence at 371 with `ALTER SEQUENCE … RESTART`, which rolls back with the transaction (`setval` does not).
4. Applies the 143 remaining canonical migrations in journal order.
   - For 14 superseded intermediate CHECKs, the body becomes a `CHECK (true) NOT VALID` placeholder.
   - Those intermediate shapes are redefined later in the same transaction.
   - Historical rows written by the out-of-order Gmail and grant migrations cannot satisfy them.
5. Writes canonical receipts for the 149 reviewed journal entries after the prefix. Later journal entries migrate normally.
6. Aborts unless the ledger is exactly the 519 canonical rows, the sequence is past them and no placeholder survives.

Before the run, compare production read-only with the fingerprint (`… production-ledger-recovery-20261023.ts --fingerprint-query`).

## Executable rehearsal

`production-ledger-recovery-20261023.postgres.test.ts` builds the reviewed state (the canonical prefix, 0403's columns, which 0542 requires, and the six migrations) in real PostgreSQL. It checks that the recovery commits to the canonical ledger and refuses a re-run. It also checks that wrong prefix hashes or timestamps, and missing or changed already-effective objects, abort without new receipts, and that a late failure restores both the ledger rows and the sequence. On that schema-only state, the repaired schema matches a canonical 519-migration build apart from one column position caused by the fixture.
