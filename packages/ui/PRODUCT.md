# Product

## Register

product

## Users

People who operate Eliza agents across desktop, mobile, and web, including
non-technical owners delegating work in chat and technical creators building,
running, and publishing projects. They move between conversational control and
focused management surfaces, often on constrained screens and with incomplete
network or Cloud availability.

## Product Purpose

Provide the shared interface through which an owner understands and controls an
Eliza agent without exposing the fragmentation of its runtimes, plugins, and
Cloud services. The Projects surface turns creating, building, running,
publishing, and managing a project into one continuous lifecycle while keeping
local-only work first-class.

Success means users always know which durable object they are acting on, what
state it is in, what an action will change, and whether a failure came from
local execution, an unavailable capability, or Eliza Cloud.

## Brand Personality

Capable, direct, reassuring. The interface should feel technically credible and
alive without becoming theatrical, dense like an IDE, or vague about system
state.

## Anti-references

- Fragmented SaaS suites that make one lifecycle look like several unrelated
  products.
- Repetitive dashboard card grids, decorative glass, gradient text, and
  ornamental motion that compete with the task.
- IDE-scale density imposed on mobile or non-technical workflows.
- Blue-accent enterprise dashboards; Eliza uses neutral surfaces with orange as
  the deliberate action and selection accent.
- Interfaces that collapse loading, unavailable, error, and legitimately empty
  into the same healthy-looking state.

## Design Principles

1. One durable object, one continuous journey: organize controls around the
   user's project rather than the backend that happens to provide a feature.
2. Local-first and honest: local work remains useful without Cloud, and remote
   dependencies expose clear unavailable or error states.
3. Familiar controls, agent parity: standard product affordances remain easy to
   scan while every meaningful mutation also has a semantic agent action.
4. Reveal complexity progressively: lead with the next useful action, then
   expose activity, runtime health, hosting, monetization, and analytics in
   context.
5. Cross-device continuity: preserve meaning, tap safety, and task progress from
   desktop through mobile rather than merely shrinking the desktop layout.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast, keyboard and screen-reader operability, visible
focus, 44-by-44 CSS-pixel touch targets, reduced-motion alternatives, and
non-color-only status communication. Copy and geometry must remain usable under
localization, narrow portrait screens, large text, loading, error,
permission-denied, and offline states.
