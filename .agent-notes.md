# Agent notes: stream Stage-1 replyText (perf/stream-final-reply)

## Path (traced)
- stage1-decision.ts: useModel(RESPONSE_HANDLER, {streamStructured:true, responseSkeleton, tools, toolChoice:required})
- model-dispatch.ts ~1278: structuredStreamFields = resolveResponseSkeletonStreamFields(skeleton) (model-policy.ts:
  DEFAULT_RESPONSE_SKELETON_STREAM_FIELDS = text, messageToUser). replyText not in set -> suppressStructuredStream -> nothing.
- If fields present: ResponseSkeletonStreamExtractor(unordered) -> downstreamChunk(chunk, accumulated, streamRevision)
  -> paramsChunk / ctxChunk (streaming context onStreamChunk = turn-lifetime wrappedOnStreamChunk -> chat-routes appendIncomingText)
- elizacloud text.ts: streamStructured -> surfaces lowest-index tool-call argument JSON deltas into textStream.
- chat-routes.ts appendIncomingText(chunk, accumulated): accumulated prefix-extends -> emitChunk (delta); else emitSnapshot (replace).
- conversation-routes.ts onChunk -> tokenWriter.writeChunk {type:token,text[,fullText every >=2048]};
  onSnapshot -> writeSnapshot {type:token, fullText} (no text = authoritative replace). reply_ready/done at end.
- Each useModel attempt = new extractor = new streamRevision, accumulated restarts -> chat-routes snapshot-replaces.
- Field priority order: shouldRespond5, contexts10, contextRequests14, intents15, replyText20, replyEffectStatus25,...

## Design (in progress)
- Gate (stage-1 owned) sees top-level fields complete BEFORE replyText starts: shouldRespond=RESPOND, contexts ⊆ [simple],
  intents/contextRequests empty, no unknown preceding keys. Otherwise the attempt holds (no stream).
- Core: GenerateTextParams.streamFields + streamFieldGate replace DEFAULT_RESPONSE_SKELETON_STREAM_FIELDS/resolveResponseSkeletonStreamFields.
- Post-hoc reroutes (replyEffectStatus after replyText, text heuristics, egress) -> final snapshot replaces; revision visible.
- BUG found: conversation-routes onSnapshot drops shrinking prefix snapshots, so a new streamRevision that restarts
  with a prefix of old text then appends -> corrupted concatenation. Fix: chat-routes passes revision resets explicitly.
- Reply-parts form (DM/API/VOICE_DM with history => replyText is array!) is common on phone; phase 2: stream text parts.
- host voice bridge throws protocol_error when authoritative text diverges from spoken text (existing fail-closed).
