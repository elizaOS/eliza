# Eliza homepage group-chat surface

- Mode: persuade.
- Audience: mainstream users who should understand Eliza without knowing agent terminology.
- User job: recognize Eliza as the useful member of a real group conversation.
- Primary action: Text Eliza. Secondary actions: Call, Telegram, and Discord.
- Proof: a fictional five-person friends chat where Eliza follows the thread, attributes speakers, summarizes settled details, and keeps one open decision visible.
- Direction: preserve the established native iMessage visual world, with recognizable iOS navigation, participant photos, sender grouping, bubbles, cards, and composer. Keep orange limited to Eliza brand and the desktop primary CTA; use neutral iOS grays and blue inside the conversation.
- Responsive contract: desktop and mobile use the same message script and participant data. Desktop presents the phone beside the value proposition; mobile turns the phone into the full-height surface and preserves the whole-screen tap target.
- Truth constraints: claim only bounded in-conversation memory. Do not imply booking, reminders, web search, message sending, durable memory, or connector availability beyond what is separately verified.
- Supporting contexts: friends, co-parenting, households, trips, and communities. Friends remain the primary demo.
- Reference: current Apple group-conversation conventions for a shared title/photo area and visible participants; this is a marketing simulation, not an exact Messages clone.
