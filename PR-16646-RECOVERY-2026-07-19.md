The evidence and Develop PR Gate rows later turned green, but those rows only validate PR metadata/gating. They did not mean the packaged App Live assertions passed. The Claude row is an independent bot startup failure after one second.

## Root cause: stale packaged harness contract, not product route failure

The default Electrobun desktop process now boots the chromeless `?shellMode=chat-overlay` main window. The packaged bridge endpoint `/main-window/eval` always evaluates that main window.

- Dispatching canonical `/views` from the chat bar correctly requests a separate launcher window in product behavior, but the test kept querying the chat-bar main window for `HomeLauncherSurface`.
- The regressions suite already opted into the full shell with `ELIZA_DESKTOP_BOTTOM_BAR=0`, but `PackagedDesktopHarness.relaunch()` rebuilt its environment and silently dropped `extraEnv`. The suite relaunches before its assertions, so `/settings#voice` was again being queried against the chat bar.
- Once the full shell was retained, Settings and the Voice content rendered. The old active-section diagnostic depended on a hidden agent-anchor attribute that was absent in the packaged DOM even though the actual Voice section was visibly mounted. Settlement now requires the existing real Voice control marker, `[data-testid="voice-section-continuous-row"]`, plus `/settings`, `#voice`, and `settings-shell`.

No production route, selector, auth, voice runtime, screenshot baseline, or threshold changed.

## Fix

- Run the inline launcher route smoke in the explicit full-window shell and continue navigating through canonical `/views`.
- Persist `PackagedDesktopHarness.extraEnv` across relaunches so test shell selection is idempotent.
- Settle `/settings#voice` against the actual mounted Voice section marker instead of a hidden agent-anchor diagnostic.
