Boot the educational kernel in QEMU.

An isolated x86-64 learning project: Multiboot2 bootstrap, page allocation and mapping, a cooperative thread scheduler, and versioned daemon messages.

This is not the ValhallaOS application or a production operating system. It does not replace the trading workspace, Eliza services, Linux images, or the existing V38 application services. Run this experiment in QEMU only, not on physical hardware.

Run the ISO

On Ubuntu/Debian, install the emulator. Then run this command from the folder containing the downloaded valhalla.iso. It uses software emulation and does not attach your host disks.

sudo apt-get update
sudo apt-get install qemu-system-x86

qemu-system-x86_64 \
  -accel tcg -m 128M -smp 1 \
  -cdrom valhalla.iso -boot d \
  -display none -serial mon:stdio \
  -no-reboot -no-shutdown

Expected terminal output includes:

ValhallaOS V38 educational baseline
PASS physical memory and virtual mapping
PASS heap and daemon boundaries
memory ready; scheduler ready; logger registered
worker says hello
worker says hello
worker says hello
PASS scheduler and daemon delivery
SELFTEST PASS

There is no shell or desktop. The kernel halts after the checks. To exit, press Ctrl+A, release the keys, then press X.

Build from source

Use an x86-64 Ubuntu/Debian host for these native-compiler commands. ARM and macOS hosts need a suitable cross-toolchain and GRUB image tools.

sudo apt-get install build-essential binutils grub-common \
  grub-pc-bin xorriso mtools qemu-system-x86 gdb

tar -xzf source.tar.gz
cd valhalla-kernel
make test
make iso CROSS=
make smoke CROSS=
make run CROSS=

CROSS= selects native x86-64 GCC. If you have the default x86_64-elf- cross-toolchain, omit that argument. The source README documents module contracts and GDB debugging.

Verify your downloads

Download all files listed in SHA256SUMS, including the three serial logs, into the same folder. Then run:

sha256sum -c SHA256SUMS

Checksums detect changed downloads. They are not code signatures or a production security guarantee.

What was actually tested

  • Host checks passed for daemon message validation, FIFO wraparound, saturation, and registration.
  • The exact merged source compiled with warnings as errors. GRUB recognized its Multiboot2 header and built the ISO.
  • Actual QEMU/TCG boots passed with 64, 128, and 256 MiB RAM. Each guest reached SELFTEST PASS and delivered exactly three worker messages.
  • Repository-wide Bun verification was unavailable in the build environment. This does not certify the application stack.
  • Automatic kernel CI is not active. GitHub rejected workflow creation because the authorized OAuth session lacks workflow scope. A reviewable template is included in the source under ci/; no permission restriction was bypassed.

Limits before you experiment

Threads and daemons share trusted kernel memory. There is no userspace isolation, exception handling, preemption, SMP, NX enforcement, networking, filesystem, or persistent storage. Interrupts are disabled. Heap allocations, page-table pages, and exited task stacks are not reclaimed.

Keep this experiment separate from production services.
